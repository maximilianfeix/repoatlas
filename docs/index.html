Built for quick orientation

Useful context, without the guesswork.

⌕Explore the whole project

Search by module, directory, or likely entry point. Cluster modules and navigate large paged results with a live map overview.

↳Inspect real import syntax

Static imports, re-exports, type imports, and literal dynamic imports or require calls. Computed calls stay visible as unresolved evidence.

⌘Resolve each project as configured

Follow npm, Yarn, and pnpm workspace exports, TypeScript aliases, custom conditions, and module resolution.

◫Audit external dependencies

Browse npm packages, Node built-ins, and URL imports separately, then open every exact import site.

⌁Estimate change impact

Follow resolved internal imports backwards to map every direct and transitive dependent module.

↗Check entry-point reachability

Spot modules outside detected entry paths or trace the shortest source-backed route to a selected module.

▦Compare architecture boundaries

See import counts between workspace packages and top-level directories, then open the exact imports.

ΔCompare architecture snapshots

Track added or removed modules and dependencies between saved repository maps.

⇱Check architecture in CI

Enforce import boundaries and cycle or reachability limits with line-level GitHub annotations, readable reports, and stable schemas.

⟳Find circular imports

Isolate strongly connected module groups and trace the import edges that keep each cycle alive.

⇩Share one portable file

Viewer and data are embedded. Open offline or share it with teammates; no servers, tracking, or AI service.

Fits your GitHub workflow

Architecture maps, built on every push.

One action creates a self-contained HTML map and uploads it to the workflow run. No API key, server, or extra permissions.

Add RepoAtlas to Actions ↗
architecture.yml artifact ready
- uses: actions/checkout@v4
- uses: maximilianfeix/repoatlas@v1.6.0
  with:
    output: repoatlas-map.html
    retention-days: 7
